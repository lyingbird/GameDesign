# 《噬变防线》功能详设 · 基因协同系统 v1.0

> 一句话：当一座塔（及其相邻塔）同时携带满足条件的基因标签时，触发额外的**协同效果**，让构筑的深度从「单塔数值叠加」升级为「基因组合的质变爆发」。

---

## 1. 设计目标与定位
- **要解决的问题**：现状（GDD v0.2）里基因只为单塔提供数值/分支成长，玩家的构筑决策退化为"哪座塔吃高数值基因"，缺乏组合深度 → 期望让**基因之间产生化学反应**，使"选哪些基因凑一起"成为核心构筑乐趣。
- **在既有游戏中的位置**：挂在**进化系统**之上、**塔防战斗**结算之中；是 GDD 支柱「少而精的协同」的直接落地，服务核心循环的"build 滚雪球"。
- **成功标准**：① 每局玩家能成型 ≥1 套协同 build；② 协同 build 的清怪效率比同等基因数的无协同配置高 30%+（数值可测）；③ 玩家测评能说出"我在围绕 X 协同做选择"。
- **Non-goals（首版不做）**：跨全场全局光环（首版只做「同塔 + 正交相邻塔」范围）；玩家自定义协同；协同的负面诅咒变体（留 P2）。

## 2. 玩家体验
- **目标体验一句话**：「两个普通基因凑到一起，突然质变成清屏组合」的发现快感（aha moment）。
- **体验流程**：三选一拿到带标签的基因 → 注意到提示"与某塔的 X 可协同" → 主动把基因喂给特定塔/调整相邻布局 → 协同成立、视觉点亮 + 伤害飙升 → 围绕该协同滚雪球。
- **情感曲线**：发现（好奇）→ 凑齐（期待）→ 触发（爽快）→ 取舍（为协同放弃高数值单卡的张力）。
- **目标玩家**：肉鸽构筑爱好者（呼应 GDD 画像），享受"组合发现"而非纯数值。

## 3. 核心机制与规则　`[程序][策划]`
**标签系统**：每个基因带 1~2 个标签，分两类：
- 元素标签：`毒` / `冰` / `火` / `雷`
- 行为标签：`扩散` / `穿透` / `暴击` / `减速`

**协同定义**：当**判定范围**内的基因标签集合 ⊇ 某条协同配方的所需标签时，该协同**激活**，对该塔附加协同效果。

**判定范围**：本塔 + 4 个正交相邻格的塔（不含对角）。标签在范围内**并集**计算。

**协同配方表（首版 6 条）**：

| 配方 | 所需标签 | 效果 | 归属乘区 |
|---|---|---|---|
| 剧毒扩散 | 毒 + 扩散 | 毒伤可传染至 2 格内敌人 | 毒乘区 |
| 寒冰碎裂 | 冰 + 暴击 | 对减速/冰冻目标暴击 +100% | 暴击乘区 |
| 烈焰穿透 | 火 + 穿透 | 火焰无视 50% 抗性并穿 3 目标 | 元素乘区 |
| 雷暴连锁 | 雷 + 扩散 | 击杀时向最近敌人连锁一次 | 元素乘区 |
| 冰火两重 | 冰 + 火 | 冷热交替，造成额外 5%/s 真伤 | 真伤乘区 |
| 致命减速 | 减速 + 暴击 | 减速目标受到的暴击伤害额外 +30% | 暴击乘区 |

**规则边界**：

| 规则 | 取值 |
|---|---|
| 单塔同时激活协同数上限 | 3 |
| 同一协同重复激活 | 不叠加（布尔，激活即生效） |
| 结算时机 | 基因变动 / 相邻塔变动时重算该塔协同集 |
| 冲突裁决 | 配方互不冲突，可并存，各自进各自乘区 |

**状态流转**：`未激活 → (范围内标签满足配方) → 激活 → (基因移除/相邻塔拆除致标签不满足) → 失活`。

## 4. 数值框架　`[数值]`
- **公式接入**：协同效果作为**独立乘区**接入 GDD §8 的塔伤害公式 `DPS = 基础攻 ×(1+Σ加法)× Π独立乘区`，新增协同相关乘区不与既有乘区同池。
- **参数基准表**：

| 参数 | 基准值 | 范围 | 说明 |
|---|---|---|---|
| 单协同伤害增益 | ×1.25 | 1.15~1.4 | 每条激活协同的乘区基准 |
| 协同乘区总封顶 | ×2.5 | — | 单塔所有协同乘区相乘的硬上限（护栏） |
| 稀有协同（冰火两重等）出现权重 | 0.5× | — | 强协同的基因抽取权重降低，稀有可遇不可求 |
| 剧毒扩散传染范围 | 2 格 | — | 防止全图传染 |

- **护栏**：协同乘区独立封顶 ×2.5；强协同基因稀有化；需 `numeric-audit` 模拟"3 协同 + 进化满层"的极限 DPS，确认不破坏 §8 的指数难度曲线。

## 5. 交互与表现　`[美术][前端]`
- **UI 元素**：基因图标右下角标签角标；塔被选中时高亮"可与之协同的相邻塔"（连线）；激活的协同在塔头显示小图标条。
- **操作流程**：选基因 → 悬停显示"可触发/差一个标签"的协同预览 → 放置后若激活，播放点亮特效。
- **反馈设计**：协同激活瞬间——塔描边发光（按元素配色）+ 短促音效 + 伤害数字变色（暴击金/毒绿/火橙）。
- **信息层级**：常驻只显示"已激活协同数"；点击塔展开完整协同明细，避免战斗中信息过载。
- **可访问性** `[美术][前端]`：协同**不只靠元素配色**区分——每个协同配独立图标 + 形状边框，伤害类型用图标而非纯颜色（色盲兜底）；元素发光辅以图标角标。
- **本地化**：标签名/协同名/悬停提示语走文本表，标为需本地化项。

## 6. 系统耦合与数据　`[程序]`
- **依赖**：进化系统（基因及其标签的来源）、塔防战斗（伤害结算管线）、布局系统（相邻关系）。
- **影响**：数值平衡（新增乘区，需与 §8 联调）；UI（新增协同展示）。
- **数据结构**：基因配置新增 `tags: string[]`；塔运行时维护 `active_synergies: SynergyId[]`；协同配方走配置表 `synergy_recipes`（id | required_tags | effect | multiplier_pool）。
- **数据流**：基因/相邻变动 → 重算该塔范围标签并集 → 匹配配方表 → 更新 `active_synergies` → 战斗结算时读取并入对应乘区。
- **埋点/数据采集** `[程序][数据]`：`synergy_activated`(配方id, 塔id, 局内时间)、`synergy_build_snapshot`(局末激活配方集)、`synergy_dps_contribution`(协同乘区贡献占比) → 用于度量 §1「每局成型 ≥1 套协同」与「协同 build 清怪效率 +30%」，并校准 §9 数值验收。

## 7. 边界、异常与防滥用　`[程序][数值]`
- **极端 case**：基因被移除/塔被卖出 → 立即重算受影响塔的协同；空范围（孤立塔）→ 仅本塔标签参与。
- **容错**：配方配置缺失/标签拼写错 → 跳过该配方并告警，不崩溃。
- **防滥用**：协同乘区封顶（§4）防"全协同一塔"清屏；相邻判定防"密集摆塔无脑全连"——可对相邻协同加 0.85× 衰减（待实测决定是否启用）。

## 8. 内容与可扩展性　`[策划][程序]`
- **首版内容量**：4 元素 + 4 行为标签；6 条协同配方；覆盖现有 6~8 塔基因池。
- **配置化**：标签、配方、乘区、权重全走配置表，策划可增删改不依赖程序。
- **扩展挂点**：新增标签/配方仅改配置；预留"三标签高级协同""跨塔光环协同"的配方 schema 字段（首版不启用）。

## 9. 验收标准
- [ ] **功能**：6 条配方均能正确激活/失活；单塔上限 3、封顶 ×2.5 生效；基因/布局变动实时重算。
- [ ] **数值**：极限配置（3 协同 + 满进化）DPS 未突破 §8 难度曲线的崩溃阈值（`numeric-audit` 通过 WARN 以上）。
- [ ] **体验**：玩家测评中 ≥70% 能说出自己在围绕某协同构筑；协同激活反馈"看得见、听得到"，色盲模式下仍可辨。
- [ ] **性能**：协同重算只在变动时触发，非每帧；千敌场景无明显卡顿。
- [ ] **测试要点（映射 §7 边界）**：基因移除→协同即时失活；孤立塔仅本塔标签参与；>3 协同时只取前 3；配方配置缺失→跳过且告警不崩溃；卖塔→相邻塔协同重算。
- [ ] **数据**：§6 三个埋点事件均正确上报，能据此算出「成型协同数 / 清怪效率」指标。

## 10. 风险与排期粒度
| 等级 | 风险 | 缓解 |
|---|---|---|
| 高 | 统治协同（某配方碾压）致策略坍缩 | 强协同稀有化 + 封顶；上线后看 build 分布快速调权重 |
| 中 | 协同乘区与进化乘区叠乘失控 | 独立乘区 + 总封顶；`numeric-audit` 必过 |
| 中 | 相邻判定让玩家"密集摆塔"破坏布局策略 | 相邻协同衰减（备选）；判定只取正交 |
| 低 | 协同提示信息过载 | 分层展示，常驻只给数量 |

**实现拆分**：
- **P0（验证爽点）**：标签字段 + 2 条配方（剧毒扩散/寒冰碎裂）+ 独立乘区接入 + 基础点亮特效 → 验证"组合质变"是否好玩。
- **P1**：补齐 6 配方 + 上限/封顶 + 完整 UI（角标/连线/明细）+ 数值联调。
- **P2**：相邻衰减、三标签高级协同、稀有协同特效。

**工作量量级**：**M**（约 2~3 周：P0 ~4 人天验证，P1 主体，P2 视反馈）。

---
**交付摘要**：本案把 GDD 支柱「少而精的协同」落地为可实现的标签+配方系统，独立乘区 + 封顶护栏防失控，配置表驱动便于扩展。建议先做 P0 两配方验证核心爽点，再接 `numeric-audit` 校准极限 DPS。
