# 装配说明：节点 8–11 如何把 designContext 装配为最终 GDD

> 前 7 个节点（`creative_intake` … `numeric_skeleton`）通过 HITL 问答把决策写入
> `designContext`（见 `gdd-schema.ts` 的 `DesignContext`）。**节点 8–11 不再向用户提问**
> （后段为"纯生成 checkpoint / 自动"），只做生成、审核、深写、验证。
> 每个节点产出一个 markdown `preview` 的 checkpoint（典型可超时自动批准），最后一节发 `final` 帧。

---

## 节点 8 `gdd_packaging`（P7 GDD 装箱）— 组合完整草稿

**职责**：把 `designContext` 1~8 章的数据**第一次完整渲染**为单段 markdown 草稿。

做什么：
1. 输出总标题行 `# 《<游戏名>》（暂名）GDD 骨架策划案 v0.2`，紧跟 `---`。
2. 按 `schema.md` 的 10 章顺序遍历 `designContext`，逐章渲染：
   - 章 `## N. 标题`，子节 `### N.M`，深层 `#### …`（不编号）。
   - 列表/表格/公式按 `gdd-schema.ts` 的类型映射：`Table` → markdown 表（`numericColumns` 右对齐），
     `Formula` → ```text``` 围栏，`Pillar/UnlockPhase` 等 → `####` 子标题 + bullet。
   - 章间插 `---`。
3. **此节先把 ch.9 内容规划的骨架写出**（scope 表、5 阶段解锁），但允许阶段验收 KPI 仍是占位，待节点 10 对齐。
4. ch.6/7/8 的表格此时可含**区间占位**（如"待定/范围"），具体单值在节点 10 深写。

产出：完整但"未审、数值未深写"的 GDD v0.1 草稿（checkpoint preview）。

---

## 节点 9 `gate_review`（P8 门禁审核）— 审核 + 修订

**职责**：对节点 8 草稿做一致性/完整性审查并就地修订，重点产出**第 10 章 风险与待定**。

检查项（gate 通过条件）：
- **章节完整性**：10 章 + ~60 子节是否齐全；缺章回填。
- **支柱一致性**：ch.6/7/8 的系统与数值是否违反 ch.3 支柱优先级（如某构筑削弱"禁书质变"）；冲突按 `pillarPriority` 仲裁。
- **反支柱合规**：ch.9.4「首版不做」是否与 ch.3.2 反支柱呼应、无矛盾。
- **资源闭环**：核对 ch.7.6 closureChecks —— "若某资源只产出不消耗，或只消耗不影响后续效率，则需调整"。
- **禁书非纯倍率**：ch.6 每本核心禁书是否答全 8 条立项问题、是否纯倍率（纯倍率数量必须为 0）。
- **风险登记**：把审查中发现的隐患落成 ch.10.1 的 6~7 条 `Risk{name, description, controls[]}`，
  **监控指标的阈值此时可留空**（由节点 11 模拟后填）。
- 同时生成 ch.10.2 待验证假设、ch.10.4 待补充项的初稿。

产出：修订后的草稿 + 风险章主体（checkpoint preview）。

---

## 节点 10 `lock_dispatch`（P9 锁版 + 数值深写）— 锁版并把骨架变成具体数字

**职责**：锁定结构（不再增删章节），把 ch.6/7/8 的**骨架/区间深写为可模拟的具体数值表**，并补全 ch.9。

做什么：
- **数值深写**：把 `numeric` 章的 8.6 Tier 任务基准表、8.7 馆区目标成本表、8.8 钥印消耗、8.9 灵墨矩阵
  从"参数区间"具化为**逐行单值**（如任务"基础文献研读 / 3 分钟 / 35 知识 / 3% 线索 / 0 灵墨 / 3 抄录"）。
- **ch.7 资源节奏表**（7.3/7.4/7.5）填入单日产出/消耗参考数字。
- **ch.6 系统表**填具体值（书灵 1~20 级、装备同标签 100%/50%/25% 叠加、铭刻/重铸成本表等）。
- **对齐 ch.9**：把节点 8 留的阶段验收 KPI 与 ch.5 各循环 KPI、ch.10.3 总表对齐到同一组数字（保持全篇 KPI 自洽）。
- 锁版：此后结构固定，节点 11 只允许调数值与补阈值，不改章节。

产出：数值完整、结构锁定的 GDD（checkpoint preview）。ch.9 内容规划由 `gdd_packaging + lock_dispatch` 共同贡献。

---

## 节点 11 `simulate_verify`（模拟验证）→ final

**职责**：用节点 10 的数值跑数值模拟，回填风险阈值与下一步建议，输出 `final` 帧。

做什么：
- **跑模拟**：依据 ch.8.11 economyModel.simulationChecks（同类衰减是否足够、单次离线收益上限、禁书倍率边界、
  装备词条是否跳过馆区节奏、书灵专长是否垄断、灵墨产出是否覆盖消耗）做闭环/曲线/异常检查。
- **回填 ch.10.1 监控指标阈值**：例如"单 Tier 内最高收益 / 基准收益 ≤ 5~8 倍"、"任务最短时长 ≥ 基础时长 20%"、
  "溢出灵墨收益 ≤ 理论值 10%"、"离线效率 ≤ 100%"。
- **收口 ch.10.3** 阶段体验验收总表（约 11 行）与 **ch.10.5 下一阶段建议**
  （```text``` 路线 `GDD v0.3 → 全量数值表 → 原型 → 离线收益模拟 → 禁书质变验证 → UI 信息架构` + 优先验证顺序）。
- **追加结尾「## 确认卡」**（见下），随后以 `final` 帧投递（`final_result.content.format:"markdown"`）。

产出：最终交付 GDD markdown（完整定稿）。

---

## 结尾固定段：`## 确认卡`

`simulate_verify` 在 `final` 前，在文档**最末尾**追加一个无编号 `## 确认卡` 段：

1. **逐章勾项**：每行一个破折号列表项，格式 `- <章名>：已覆盖/已补充，<一句摘要>`，覆盖全部 10 章 + 关键子系统
   （禁书/书灵/离线/馆区/装备/资源/数值/内容/风险）。参考示例：
   ```
   - 游戏概述：已覆盖，一句话描述、品类、题材、目标平台假设、MVP 技术假设、核心卖点完整。
   - 禁书系统：已补充 8 本核心禁书样例，明确规则改写、构筑影响、副作用与非倍率设计。
   - 离线收益：已补充完成次数、未完成进度、队列耗尽、溢出时间、异常时间处理。
   ```
2. **状态 JSON 块**：一句"GDD 骨架确认状态："后跟 ```json``` 围栏：
   ```json
   {
     "version": "v0.2",
     "phase_complete": true,
     "status": "READY_FOR_PROTOTYPE_AND_NUMERIC_TABLES",
     "summary": [
       { "dimension": "完整性", "value": "10/10章节已覆盖，并补充关键样例表" },
       { "dimension": "一致性", "value": "符合禁书质变、长线挂机、馆区苏醒、多系统构筑支柱" },
       { "dimension": "可落地性", "value": "已具备进入原型、数值表和离线模拟的最小闭环" },
       { "dimension": "主要剩余工作", "value": "全量任务表、全量节点表、全量技能/装备数值、UI信息架构、模拟验证" }
     ]
   }
   ```

`status` 取值对应阶段闸门：骨架阶段恒为 `READY_FOR_PROTOTYPE_AND_NUMERIC_TABLES`。
`summary` 四维（完整性 / 一致性 / 可落地性 / 主要剩余工作）是 `simulate_verify` 自评的固定维度。
