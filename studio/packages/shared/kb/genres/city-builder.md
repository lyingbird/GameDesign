# 城市建造 (City Builder)

## 核心循环
规划布局 → 建造（住宅/生产/服务/基础设施）→ 人口增长产生需求与税收 → 用资源/资金扩张并解决涌现问题（拥堵、污染、短缺、不满）→ 解锁更高级建筑/区域 → 城市规模与复杂度螺旋上升。核心快感是**"从无到有规划并目睹一座城市/聚落生长繁荣的造物主满足感 + 平衡多重需求的系统优化"**。是模拟经营的空间/成长向子类。

## 关键子系统
- **建造与区划 (zoning)**：住宅/商业/工业分区或具体建筑放置，布局即玩法。
- **资源/供需链**：人口需要食物/水/电/工作/服务，建筑产出与消耗形成供需网络，短缺即危机。
- **基础设施与物流**：道路/管线/交通——连通性与拥堵是核心 puzzle（SimCity/天际线的灵魂）。
- **人口/市民系统**：人口增长、满意度/幸福度、需求层级（生存→服务→娱乐）。
- **经济/财政**：税收、建造与维护成本、预算平衡。
- **解锁/成长**：人口里程碑解锁新建筑/政策/区域，提供进度感。
- **挑战层**（可选）：灾害、敌袭、季节、生存压力（区别于沙盒纯建造）。

## 经济/数值要点
- **供需平衡是核心数值**：每种资源的产出率 vs 消耗率需可调可视，短缺/过剩驱动玩家决策。
- **维护成本 vs 收入**的财政曲线：扩张带来收入也带来维护负担，制造"扩张速度"的取舍。
- 人口增长曲线与需求解锁咬合：人多了才需要更高级服务，服务到位才能继续增长（正反馈链需有节制）。
- **空间/物流约束**是城建独有的难点：距离、覆盖半径、运输容量——把"摆放"变成有意义的优化。
- 避免后期"钱多到溢出"使财政失去意义（需持续的成本天花板/新需求）。

## 经典参考作品
- **Cities: Skylines**：现代城建标杆，深度交通模拟 + 区划 + 服务覆盖 + 政策，物流/拥堵的核心玩法天花板。
- **SimCity 2000/4**：品类奠基，区划 + 公共服务 + 灾害，定义"市长模拟"。
- **Banished**：中世纪生存村庄，资源链紧张 + 人口存亡，把城建推向生存方向。
- **Frostpunk**：生存城建 + 道德抉择，把"建城"包裹在极端生存与社会压力中，叙事与系统融合典范。
- **Anno 系列**：供应链 + 贸易航线 + 多岛经营，城建 + 经营深度结合。
- **Townscaper / 极简建造**：理解"纯造物"无管理压力的休闲变体下限。

## 常见坑
- **后期管理疲劳**：城市变大后微操繁琐、性能下降（成千上万实体的模拟性能是技术难点）。
- 没有"压力源"则沦为无目标的摆放沙盒（部分玩家爱，但缺乏驱动力）。
- 供需/物流系统不透明，玩家看不懂为何短缺/拥堵（数据可视化是刚需）。
- 财政失衡：前期破产劝退或后期钱多到无意义。
- 美术/建筑资产量大（多样建筑外观），是内容成本。

## 单人/小团队可行性
**中等**。系统/逻辑驱动、无联机压力，但有两个特定负担：① **大规模实体模拟的性能**（成千上万市民/建筑的更新，物流寻路）是真实技术难点；② **建筑美术资产量**较大。小团队务实策略：① **缩小规模**——做小型聚落/村庄而非百万人口大都市（Banished 思路）；② **加生存/叙事压力**把"建造"聚焦成有目标的体验（Frostpunk 思路），用压力替代海量内容；③ 抽象化/网格化降低美术与模拟成本（体素/低多边形/2D 俯视）；④ 用清晰的供需可视化撑起系统深度。聚焦一个独特的"约束/主题"（极寒、孤岛、地下）比追求 Cities: Skylines 的体量更现实。
