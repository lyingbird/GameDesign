# 格斗 (Fighting Game)

## 核心循环

观察对手距离与状态（血量、资源槽、角色位置）→ 判断当前攻防形势（进攻/防守/中距博弈）→ 输入指令执行动作（搓招、连段起手、防御、投技）→ 对手响应（防御/反击/被击中）→ 根据结果调整节奏（继续连段 / 退守 / 施压）→ 率先将对手血量清空获胜，通常以局为单位（先赢若干局）。核心快感是**"读取对手心理 + 精准执行的双重博弈"**——格斗游戏既是反应与手速的考验，更是信息博弈与心理对抗的竞技；同一套连段在高手对局中可能只是开路工具，而非胜负本身。

## 关键子系统

- **帧数据（frame data）**：游戏以帧（通常 60fps）为最小时间单位，每个动作有启动帧（startup）、持续帧（active）、后摇帧（recovery）之分；攻击命中后对手的硬直帧数决定是否可继续追击（有利帧/不利帧）；确反（punish）是指对手动作不利帧内己方反击的保证伤害窗口，帧数据是格斗游戏策略的数学基础。
- **连段（combo）与取消（cancel）**：普通攻击→特殊技→超必杀的取消链构成连段骨架；取消时机通常有严格帧窗（链取消、特殊取消、超取消各有不同规则）；连段是伤害输出的主要途径，也是技术表达的核心。
- **判定框（hitbox / hurtbox）**：攻击判定框（hitbox）与受击判定框（hurtbox）决定双方互动是否成立；两者的精细设计直接决定角色在中距离的博弈强度与特定技能的实用性。
- **输入系统（搓招 / motion input）**：波动拳式（↓↘→ + 攻击）、龙卷式、旋转指令等是传统格斗游戏的身份标志；现代格斗游戏（如街霸6的现代操作模式）提供简化输入以降低门槛，但核心玩法层保持兼容。
- **资源管理**：超必杀槽（meter）、EX技、V-Gauge 等资源系统给每局加入资源积累与消耗的策略层；何时使用 EX 确反、何时保留资源防御反转，是高层博弈的关键决策点。
- **网络代码（netcode / 回滚网络）**：对战格斗的联机核心；延迟补偿方案分为延迟帧（delay-based）和回滚（rollback netcode）两派；回滚网络（GGPO 等）以本地预测+状态回滚换取响应流畅，已成为现代竞技格斗的联机标准。
- **角色平衡**：多角色竞技游戏中每个角色的技能、属性、连段路线须保持整体平衡；发布后持续通过补丁微调数值是长线运营的常态。

## 经济/数值要点

- **伤害计算**：连段伤害通常有缩放机制（combo scaling），连段越长单次命中伤害递减，防止单次连段过于致命（一段秒杀）；确认（confirm）是指从命中确认到执行完整连段的流程，攻防节奏由伤害缩放比例塑造。
- **血量与攻防比**：角色血量决定一局时长与容错；攻强防弱的设计拉快节奏，防强攻弱则拉长博弈；典型平衡目标是使单次正确读取（一次确反连段）不能直接结束比赛。
- **资源槽增速与用途**：meter 的积累速率（受击/命中各自加成）与消耗用途（EX 确反/超必杀/防御反转）影响全局攻防节奏，设计时需平衡攻防双方受益。
- **角色强度分级（tier）**：在多人竞技中角色强度分布是可接受的，但顶层强度与底层的差距不宜过大（通常 S/A/B/C tier 差异在有限连招效率上体现，而非一刀切）；持续数据驱动的补丁是必要运营成本。
- **输入窗口宽容度**：搓招输入窗（通常 ±2-3 帧）与链取消时序直接决定技术上限；过窄劝退新手，过宽丧失技术差距——如何分层（新手简化 / 高手经典输入并存）是现代设计的核心取舍。

## 经典参考作品

- **街头霸王 6（Street Fighter 6）**：现代操作模式 + 经典模式双轨降低门槛，驾车模式世界赛场系统是近年格斗最佳新人引导；帧数据、确反逻辑的教科书级实现。
- **铁拳 8（Tekken 8）**：3D 格斗的现代标杆，侧步系统与轴向博弈构成区别于 2D 的核心差异；角色技能深度极高，Heat 系统重塑进攻节奏。
- **罪恶装备 Strive（Guilty Gear Strive）**：Arc System Works 的动画渲染演出与精密帧数据设计的结合，RC（Roman Cancel）系统为连段创造力提供极大空间；画面/声音/手感全面标杆。
- **任天堂明星大乱斗 特别版（Super Smash Bros. Ultimate）**：平台格斗子类型的顶峰，以击飞百分比替代血量的创新机制，角色数量（80+）与平台场景设计开创独特竞技生态。
- **真人快打 1（Mortal Kombat 1）**：画面演出与Fatality系统是格斗游戏视觉冲击力的极致示范；Kameo 辅助系统提供辅助角色搭配策略层。
- **Skullgirls**：极小团队制作的 2D 格斗精品，L-canceling 与连段系统设计精密，动画帧质量业界认可；对独立格斗游戏的可能性有重要参考价值。

## 常见坑

- **帧数据设计欠缺或未公开**：不透明的帧数据使玩家无法建立正确的博弈认知，高阶玩家被迫自行逐帧测算补全，但会破坏信任感；现代格斗游戏应在训练模式内置帧数据显示。
- **新人引导断层**：格斗游戏学习曲线极陡（搓招精度 + 帧数据理解 + 对局阅读同时要求），缺乏分层教学（入门教程 → combo 训练 → 对局分析）会导致绝大多数玩家在第一小时放弃。
- **回滚网络代码缺失**：2024 年后竞技格斗若仍使用纯延迟帧联机，联机体验与竞技氛围将直接崩溃；回滚 netcode 已是硬性门槛而非加分项。
- **角色平衡严重失衡**：单个角色在多数对局中存在压倒性优势（即俗称"破格"）会迅速毁掉竞技生态，须有持续数据监测与补丁响应机制。
- **连段窗口过窄或过宽**：过窄的取消窗口使普通玩家无法体验核心连段乐趣；过宽则消除技术差距；两者皆破坏长期留存动力。
- **忽视本地多人（本地 PVP）**：格斗游戏的社交性起源于街机厅面对面对战，忽视本地分屏与低延迟本地对战体验会损失核心社群黏性。

## 单人/小团队可行性

**极难，是独立团队最高风险的竞技品类之一。** 核心挑战来自三个方向叠加：其一，帧精度的技术要求——所有动作需逐帧校对判定框与帧数据，通常需要专用内部工具（hitbox 编辑器、帧步进调试器），开发周期远超同体量其他品类；其二，角色平衡的长期成本——多角色对战游戏即使发布后也需要持续监测数据与发布补丁，这对小团队是无休止的维护负担；其三，联机基础设施——回滚 netcode 的实现（或集成 GGPO 等库）本身是一项重大工程任务，且需要大量真实对局数据验证。Skullgirls 是小团队成功案例，但其团队成员拥有资深格斗游戏从业经验，开发历时数年。务实建议：若坚持做格斗类，优先选择**平台格斗（Smash-like）**子类型——平台物理模型相对通用，判定可借助成熟引擎，角色数量可控；或做**单人/合作清版格斗**（beat 'em up），规避 PVP 平衡与联机成本；避免在首款作品中挑战多角色竞技对战格斗。
