# 核心幻想：玩家幻想、目标用户画像、情感目标

## 核心概念

核心幻想回答"**玩家为什么想玩**"——不是机制，而是机制背后玩家想成为/感受到的东西。它是 GDD 第二章，承上（创意接入定下的题材/品类）启下（设计支柱由它萃取）。三部分：

**玩家体验一句话（fantasy statement）**：用"玩家扮演 X，做 Y，最终 Z"的句式，把幻想浓缩成一句。
> 玩家扮演一名典藏图书馆，在尘封书库里驯服危险知识，让整座魔法图书馆逐层苏醒，并最终引发知识爆炸。
要点：有**角色身份**（馆长）、有**核心动作**（驯服知识）、有**情感弧线/终极愿景**（苏醒→爆炸）。

**目标用户画像（target persona）**：不是人口统计，而是**玩家偏好画像**——他们喜欢什么样的乐趣、能接受什么节奏、不要什么。画像通常列 5~8 条偏好特征（如：喜欢长线积累、能接受小时/天/周节奏、喜欢多线成长、喜欢构筑优化、关注离线效率、享受"下次上线变强"、不要求高频实时战斗），末尾点出**核心乐趣**："不是瞬时刺激，而是制定路线、优化配置、等待收益、突破瓶颈"。
- 画像的作用：它直接约束后续每个设计决策"这个目标玩家会喜欢吗"。

**情感目标（emotional goals，3~5 条）**：游戏要在玩家心里激起的具体情绪，每条配"靠什么机制兑现"。以《典藏图书馆》为例：
- 掌控危险知识的**成就感** ← 禁书研究
- 图书馆苏醒的**期待感** ← 修复/解锁
- 长期规划被兑现的**满足感** ← 离线结算体现昨日配置
- 规则被改写的**惊喜感** ← 解读核心禁书
- 构筑优化的**研究感** ← 系统协同
要点：情感目标必须**可被某个机制兑现**，否则是空话。

## 在问答中如何用（core_fantasy 节点）

core_fantasy 节点为 question → checkpoint 结构。harness 用本卡（并叠加 mda-framework 卡作为透镜）：

1. **先定幻想一句话**。基于 creative_intake 已确认的题材/品类，提"玩家在这个游戏里想成为谁、做什么、最终体验到什么？"给一个推荐句（带角色/动作/愿景三要素），option_id:0 让玩家改写。
2. **画目标玩家像**。问"什么样的玩家会爱上它？他们能接受什么节奏、不要什么？"用偏好（非人口统计）描述，列 5~8 条特征 + 一句"核心乐趣"。校验：画像与品类一致（挂机玩家≠硬核动作玩家）。
3. **抽 3~5 条情感目标，每条挂机制**。问"你最想让玩家产生哪几种情绪？"对每条追问"靠什么系统/时刻兑现？"——用 MDA 透镜：从 Aesthetics（目标情绪）倒推 Mechanics（兑现它的机制）。
4. **生成核心幻想卡（一句话 + 画像 + 情感目标×机制）作为检查点**。
5. **为下游埋点**：情感目标 → design_pillars 的支柱候选来源；画像 → 后续所有节点的"目标玩家会喜欢吗"校验基准。

收敛判据：幻想一句话（三要素齐）+ 偏好型画像（含核心乐趣）+ 3~5 条情感目标（每条挂机制）→ 出检查点。

## 反模式/坑

- **把机制当幻想**："这是一个挂机+卡牌游戏"——这是品类不是幻想。幻想是玩家**想成为/感受**什么。
- **画像写成人口统计**："18-35 岁男性"——无法指导设计。要写偏好画像（喜欢什么乐趣、能忍什么节奏）。
- **情感目标不挂机制**：列一堆情绪却没说靠什么兑现 → 落不了地。每条情绪必须对应一个机制/时刻。
- **幻想与品类矛盾**：说要"紧张刺激的肾上腺素"，品类却是慢节奏挂机 → 体验撕裂。幻想与品类节奏要自洽。
- **幻想太泛**："带来快乐"——对任何游戏都成立=没说。幻想要有这个项目独有的角色身份与情感弧线。
- **跳过情感弧线**：只说"扮演馆长"不说"最终怎样" → 缺乏长线愿景拉力。一句话里要有终极愿景（苏醒→爆炸）。
