# 设计支柱与反支柱：Must-Have / Won't-Do / 优先级

## 核心概念

设计支柱是项目的**决策宪法**：当任何后续设计冲突出现时，用它来裁决"保哪个、砍哪个"。它由三部分组成：

**Must-Have 设计支柱（3~4 条）**：项目"必须成立"的核心体验承诺。每条支柱：
- 一句话标题（如"禁书驱动系统质变"）。
- 一段**可检验的设计要求**（不是口号，是约束）。例如支柱"长线挂机规划"展开为：玩家离线也能推进、目标以小时/天/周组织、成长可预期不纯随机阻断、配置影响效率、不靠频繁点击。
- 第一条支柱通常是**差异化核心**（项目区别于竞品的根本，优先级最高）。

**Won't-Do 反支柱（2~3 条）**：明确"坚决不做"的事，划定边界、保护 scope。每条说清不做什么 + 为什么。成熟设计范式中，反支柱通常直指最常见的 scope 膨胀来源：
- 不做高频手操/实时反应战斗（与挂机定位冲突）。
- 不做永久损失惩罚（保护长线积累，可有副作用但可恢复）。
- 不做强制社交协作（首版保证单人体验成立）。
反支柱是 scope 纪律的硬约束，比"待办列表"更有力——它让"不做"成为正式承诺。

**支柱优先级（全序排列）**：当支柱之间冲突时的裁决顺序，用 `>` 排成一条全序链。
> 禁书驱动系统质变 > 长线挂机规划 > 图书馆逐层苏醒 > 多技能装备协同
并给**具体裁决示例**："当装备构筑削弱禁书质变感时，优先保护禁书"——让优先级可操作，而非摆设。

## 在问答中如何用（design_pillars 节点）

design_pillars 是**多轮 question**节点。harness 用本卡：

1. **从 core_fantasy 萃取支柱候选**。基于已确认的核心幻想/情感目标，提"这个游戏'必须做到'的 3~4 件事是什么？"给推荐支柱（每条带一句理由），option_id:0 让玩家增删。
2. **把每条支柱"展开成约束"**。对每条追问"这条具体意味着设计上要满足什么/不能违反什么"，落成可检验的设计要求清单（≥4 条/支柱）。模糊口号不算支柱。
3. **专门追问反支柱**。问"为了不让 scope 失控，这个游戏坚决**不做**哪些事？"重点引导砍掉高频操作、强社交、重惩罚、重叙事等高成本项（呼应 scope-discipline 卡）。给推荐 + 理由。
4. **强制排优先级**。问"如果支柱A和支柱B冲突，先保哪个？"逼出一条全序链，并要一个冲突裁决示例。
5. **生成支柱卡（Must/Won't/优先级三段）作为检查点**。让玩家确认"这就是项目的决策宪法吗"。

收敛判据：3~4 条带可检验要求的 Must-Have + 2~3 条 Won't-Do + 一条全序优先级链（含裁决示例）→ 出检查点。

后续所有节点（系统/数值/内容）做取舍时，harness 都应回引这张支柱卡做一致性检查。

## 反模式/坑

- **支柱是口号不是约束**："好玩""有深度""沉浸感"——无法裁决任何冲突。支柱必须能展开成"要满足X、不能做Y"的可检验要求。
- **支柱太多（5+）**：等于没有支柱，无法形成优先级。控制在 3~4 条。
- **没有反支柱**：只说做什么不说不做什么 → scope 无边界、必膨胀。Won't-Do 是最有价值的部分，单人/小团队尤其要狠。
- **优先级是平级**：不排全序 → 冲突时无法裁决。必须 `A > B > C`，并给裁决示例。
- **第一条不是差异化**：把通用品质（"操作手感好"）放第一 → 项目没有灵魂。第一支柱应是"这游戏凭什么和别人不一样"。
- **支柱与幻想脱节**：支柱凭空来，不呼应 core_fantasy 的情感目标 → 体验割裂。支柱应是核心幻想的"工程化承诺"。
