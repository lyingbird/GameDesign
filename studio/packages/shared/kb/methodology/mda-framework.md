# MDA 框架：Mechanics-Dynamics-Aesthetics（作为透镜）

## 核心概念

MDA（Hunicke, LeBlanc, Zubek, 2004）是一把分析游戏的经典透镜。三层：

- **Mechanics（机制）**：规则、数据、算法——设计师直接编写的东西。例：任务时长公式、资源产出、装备词条。
- **Dynamics（动态）**：机制在玩家操作下**运行时涌现**的行为。例：玩家为最大化离线收益而调整书灵专长配置、围绕某禁书规则形成构筑流派。
- **Aesthetics（美学/体验）**：玩家最终感受到的情绪反应。LeBlanc 的 8 种美学：感官（Sensation）、幻想（Fantasy）、叙事（Narrative）、挑战（Challenge）、伙伴（Fellowship）、发现（Discovery）、表达（Expression）、消遣（Submission/放松）。

**核心洞见（方向性）**：
- **设计师从左往右造**：写机制 → 机制涌现动态 → 动态产生体验。
- **玩家从右往左体验**：先感受到美学（"好爽/好满足"）→ 注意到动态 → 最少意识到机制。
- 因此**设计要从右往左想**：先定"想让玩家有什么感受（Aesthetics）"，再倒推"什么动态能产生它"，最后落到"写什么机制"。这正是 core_fantasy 定情感目标、再挂机制的逻辑。

**作为透镜的两个用法**：
1. **正向校验**（design_pillars）：每条支柱/系统，问"它产生什么动态？这些动态指向哪种美学？是否服务于目标情感？"——揪出"有机制但产生不了想要的体验"的空转设计。
2. **反向设计**（core_fantasy）：从目标美学（情感目标）出发，问"哪种动态能涌现这种感受？需要什么机制支撑？"——避免"先堆机制再硬凑体验"。

## 在问答中如何用（core_fantasy + design_pillars 节点）

本卡作为**透镜叠加**在这两个节点的主卡（core-fantasy / design-pillars）之上，不单独驱动问答，而是给 harness 提供提问的**思考结构**：

**在 core_fantasy**：
- 定情感目标时，从 8 种美学里**选 2~3 种主导美学**作为推荐项（如挂机经营品类主推 Discovery+Expression+Submission，理由：发现新系统、表达构筑、放松挂机）。
- 对每个情感目标，提问引导玩家说出"什么样的玩家行为（动态）会带来这种感受"，再由后续节点落成机制。

**在 design_pillars**：
- 评估每条候选支柱时，用 M→D→A 链检查："这条支柱写的是机制还是体验？它涌现什么动态？动态服务哪种美学？"——帮助把"机制型伪支柱"升级为"体验型真支柱"。
- 用它揪反模式：若某系统产生不了任何指向目标美学的动态，提示玩家这是 scope 浪费（呼应 Won't-Do）。

**一致性校验**：harness 可对产出做轻量检查——情感目标（A）应能追溯到某些动态（D），动态应有机制（M）支撑；三者断链则提示补全。

## 反模式/坑

- **只造机制不想体验（左→右单向）**：堆了一堆系统，却没想清楚玩家会感受到什么 → 系统空转。永远从 Aesthetics 倒推。
- **把美学当机制写**："要有沉浸感"不是机制，是 Aesthetics；要追问"什么动态产生沉浸、什么机制支撑那个动态"。
- **忽略 Dynamics 中间层**：直接从"想要紧张感"跳到"加个倒计时"，不分析玩家实际会涌现什么行为 → 常造出反效果（倒计时反而让人焦虑退游）。
- **美学贪多**：想同时满足全部 8 种 → 体验模糊。选 2~3 种主导美学，与品类/画像匹配。
- **把 MDA 当成要写进 GDD 的章节**：MDA 是**思考透镜**不是交付物。它的产物是更好的情感目标和支柱，而不是一段"本游戏的 MDA 分析"。
