# 风险与验证：已知风险、待验证假设、验收指标

## 核心概念

GDD 的最后一章（「风险与待定」由 gate_review + simulate_verify 产出）不是免责声明，而是**把全篇的不确定性显式化、并给出验证方式**。三部分：

**已知风险（known risks，按优先级）**：点名最可能让设计崩坏的几件事，标出**最高优先级风险**。数值类游戏通常首要点名：
> 最高优先级风险：**叠乘爆炸 + 离线收益穿透**
风险应具体到机制（不是"可能不好玩"），并能追溯到某个公式/系统。常见风险类型：
- **数值类**：叠乘爆炸、通胀/通缩、被动收益穿透、单路线垄断（某构筑碾压其它）。
- **节奏类**：早期卡死、中期断层、后期软墙变硬墙。
- **闭环类**：某资源只产不耗、消耗不回流、解锁只给倍率不给入口。
- **scope 类**：内容量黑洞、系统协同失控、UI 维护膨胀（成熟实践表明：主要风险通常不是原型，而是内容量/平衡/协同/UI）。

**待验证假设（assumptions to validate）**：把"我们以为成立但还没证"的点列成清单，每条配**怎么验**。数值章末尾的"需在后续模拟中验证"清单通常包括：
- 同类加成衰减是否足够（防爆炸）；
- 单次离线收益上限是否合理（防穿透）；
- 规则倍率边界是否过高；
- 装备词条是否导致跳过节奏；
- 专长叠加是否导致单路线垄断；
- 软回收资源产出是否覆盖消耗但不溢出。
还包括 MVP 技术假设（如：离线计时用本地时间+服务器校验接口、异常时间保护、离线结算需可复算可追踪、首版不做强反作弊）。

**验收指标（acceptance metrics）**：可量化的"算通过"标准。复用循环节点已定的验收指标（如：首次反馈 ≤5 分钟、首个核心解锁 2~4 小时、首版体验 4~6 周）+ 经济指标（各资源日产消在区间内、无某资源溢出、无单构筑碾压）。每条 = 指标 + 目标值 + 判定方法（模拟/playtest）。

**模拟验证（simulation）逻辑**（simulate_verify 节点核心）：用数值模型跑一遍经济，验证：产出/消耗是否在区间、有无爆炸/穿透、成长曲线是否"前快中稳后软墙"、是否存在卡死点或垄断构筑。任何一项不过 → 回标对应假设/风险，建议调参方向。

## 在问答中如何用（gate_review + simulate_verify 节点）

这两个节点为**自动生成 checkpoint**（无用户提问），simulate_verify 末尾发 `final`。harness 用本卡**汇总全篇产出做体检**，不新提问：

**在 gate_review（门禁审核 + 修订）**：
1. **跨章一致性体检**：核对幻想↔支柱↔循环↔系统↔资源↔数值是否自洽（差异化锚点=第一支柱=P0系统？情感目标都有机制兑现？每资源源汇齐全？每公式有衰减/上限？）。
2. **生成已知风险清单**：从数值/经济/scope 章节抽取高危点，标最高优先级风险。
3. **生成待验证假设清单**：把所有"建议区间""首版假设"转成"需验证：X 是否成立，验法 Y"。
4. **修订**：对体检发现的断裂点（如某资源只产不耗、某系统无优先级）就地修订或标注。

**在 simulate_verify（模拟验证 → final）**：
1. **跑经济模拟**（按 numeric_skeleton 的公式 + 区间），输出：各资源日产消是否在区间、有无叠乘爆炸、离线是否穿透、曲线是否符合预期、有无卡死/垄断。
2. **对每条待验证假设给结论**（通过/风险/需调参 + 建议方向）。
3. **生成验收指标表**（指标/目标/判定法），作为交付标准。
4. **产出最终 GDD 的风险章** + 下一步建议（先做哪个 P0、先验哪条假设）。

收敛判据：已知风险(标最高优先级) + 待验证假设(每条带验法) + 验收指标表 + 模拟结论 → 发 final。

## 反模式/坑

- **风险写成免责声明**："可能不好玩/有不确定性" → 没信息量。风险必须具体到机制（哪个公式会爆、哪个资源会断），可追溯、可验证。
- **假设不带验法**：列了"离线可能穿透"却不说怎么验 → 无法行动。每条假设配"用模拟/playtest 验 X，目标值 Y"。
- **验收指标不可量化**："手感要好" → 无法判定。指标必须有目标值和判定方法。
- **不标最高优先级风险**：风险平铺 → 不知道先防哪个。必须点名 top 风险（通常是数值爆炸/经济穿透）。
- **门禁不做跨章一致性检查**：各章自说自话、差异化锚点和支柱对不上 → GDD 内部矛盾。gate_review 的首要职责是跨章自洽体检。
- **模拟只看"能不能跑"不看"健不健康"**：只验证公式不报错，不验有无爆炸/卡死/垄断 → 漏掉真正的设计风险。模拟要对照区间和曲线形状判健康度。
- **忽略 MVP 技术假设风险**：挂机/联网类不点明"时间作弊、离线复算、存档校验"等技术假设 → 上线翻车。技术假设也要进待验证清单。
