# Scope 纪律：MVP 取舍与"首版不做"

## 核心概念

Scope 纪律 = 在保住核心体验的前提下，**主动、明确地把高成本/低差异化的内容推迟或砍掉**。对单人/小团队，scope 失控是头号死因。原则不是"做得少"，而是"**先做能验证核心循环的最小集合，把不确定性砍掉**"。

**"首版不做（Won't-Do v1）"清单**：和 design_pillars 的反支柱呼应，但更具操作性——它是一张明确的**推迟/砍除清单**。以《典藏图书馆》为例，系统性砍掉/降级了：
- **社交/竞争**：反支柱"不做强制社交协作"——无公会、组队、好友互助、排行依赖。首版保证单人长线成立。
- **高频/实时操作**：反支柱"不做高频手操与实时反应战斗"——与挂机定位冲突，且开发/打磨成本高。
- **重惩罚/永久损失**：反支柱"不做永久损失"——保护长线积累，降低劝退。
- **重度进度系统降级**：装备系统标 P2（"首版轻量实现，不应完全砍掉"）、品质先做 3 档、技能节点压到 25~30 个、装备词条组合 30~50 组、核心内容单元约 8 个——都是"够验证、不膨胀"的克制量。

**砍 scope 的三类常见对象**（harness 默认建议优先砍/推迟）：
1. **社交与竞争系统**（公会/PVP/排行/交易）：网络与平衡成本高，且 MVP 阶段无法验证留存核心。
2. **高频/实时操作**（动作战斗/QTE/实时 PVP）：美术与手感打磨成本极高，与多数慢节奏品类冲突。
3. **重度进度/海量内容**（海量技能/怪物/图鉴/多结局叙事）：内容产能黑洞。先做"足够跑通循环"的小集合，留扩展接口。

**MVP 闭合（MVP closure）判据**：MVP 必须能**完整跑通核心正反馈链一整圈**（产出→消耗→解锁→质变→反哺）。任何不在这条链上的系统都是 P2 或"首版不做"。判断每个系统时问："砍了它，核心循环还能闭合吗？"——能，则降级/推迟。

**降级语言而非二元砍除**：用"P2 轻量实现/首版 3 档/接口预留"等克制表述，而非粗暴删除——既控成本又不堵死后续扩展（常见表述如"MVP 假设""首版不做强对抗，但需可复算""预留云存档接口"）。

## 在问答中如何用（genre_scope + systems_resources 节点）

**在 genre_scope**（定体量时）：
1. 给 Scope 推荐时，**默认主动提出"首版不做"候选**：问"社交/竞争、实时操作、海量内容这几类，首版要不要砍/推迟？"给推荐（砍，理由：成本高、不在核心循环上、可后续加），option_id:0 让玩家保留。
2. 把砍除项落成明确的"首版不做"清单，呼应反支柱。

**在 systems_resources**（列系统时）：
1. **每个系统强制标 P0/P1/P2**（见 systems-prioritization 卡），P2 默认"轻量实现"，超出 MVP 闭合的系统标"首版不做"。
2. 对每个非 P0 系统问"砍了它核心循环还闭合吗？"——闭合则降级。
3. 对重度系统（装备/技能/内容）**主动建议克制量**：技能节点数、词条组合数、品质档数、内容池大小——都给"够验证的小数 + 后续可扩"的推荐。
4. **用降级语言**生成产出（"P2 首版轻量""先做 3 档""预留接口"），而非删除。

收敛判据：每个系统有优先级标注 + 明确的"首版不做"清单 + MVP 能跑通完整正反馈链 → 通过 scope 校验。

## 反模式/坑

- **既要又要**：核心循环还没验证就想加社交、竞技、叙事 → 全做不完、全做不精。先闭合核心循环。
- **没有"首版不做"清单**：只列要做的，不列不做的 → 需求会无限蔓延。明确写下推迟/砍除清单。
- **平均用力**：每个系统都做"完整版" → 产能耗尽在非核心系统。P0 做透，P1 够用，P2 轻量。
- **砍掉核心循环上的系统**：为省事砍了离线结算或门槛资源 → 核心循环断裂、MVP 不闭合。砍 scope 的前提是"砍后循环仍闭合"。
- **二元思维（要么全做要么不做）**：把"复杂装备系统"整个砍掉，而不是降级为"3 档品质 + 30 组词条" → 丢失差异化或体验。优先降级而非删除。
- **不留扩展接口**：砍得太死，后续想加要重构 → 用"MVP 假设 + 预留接口"的方式克制，给未来留路。
